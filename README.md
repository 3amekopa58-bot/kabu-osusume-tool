# 株おすすめツール（自分専用）

日本株（日経225構成銘柄）を対象に、「割安度（PER・PBR・配当利回り）」と
「トレンド（移動平均・下半身・押し目買い等）」をスコア化して合算し、
おすすめ順にランキングするツール。

---

## ⚠️ 最初に読むこと：このツールはインデックス投資に勝っていない

2026-08-29に、予算制約・売買手数料・スリッページ・ETFコスト・**税金**を
すべて織り込んだポートフォリオシミュレーション（`portfolio_sim.py`）を
行った結果、**このツールの売買ルールは日経平均のインデックスファンドを
買い持ちするより成績が劣る**ことが分かった。

| 期間 | 本ツールの戦略（税引き後） | 日経平均を買い持ち（納税後） |
|---|---|---|
| 10年 | +160.2% | **+235.2%** |
| 27年 | +142.5% | **+224.9%** |

- 税引き**前**なら戦略がわずかに勝つ（27年 +313.5% vs +282.3%＝+31.2pt）が、
  この程度の差では売買のたびの課税で簡単に吹き飛ぶ
- NISAでの回避も、成長投資枠が年240万円しかなく本戦略の年間買付
  800〜1,000万円をカバーできないため2〜3割が限度
- 詳細は [REQUIREMENTS.md](REQUIREMENTS.md) の 4.4-4 を参照

**それでも個別株をやりたい／銘柄選びを楽しみたい、という前提で使うこと。**
「インデックスより儲かるツール」ではない。

## 現在の仕様

- **対象銘柄**: `tickers.csv` に列挙した225銘柄（日経225構成銘柄）
- **予算**: 100万円（`screen.py` の `BUDGET`）。日本株は100株単位で買うため、
  1単元が予算を超える銘柄は自動で除外される
- **データ取得**: yfinance（無料・登録不要）＋ EDINET（財務データの一部）
- **スコア**: 割安度スコアとトレンドスコアを 50:50 で合算
  （`FUNDAMENTAL_WEIGHT` / `TECHNICAL_WEIGHT` で調整可）

### 売買ルール（バックテストで検証済み）

- **買い**: 「下半身」または「押し目買い」のどちらかが点灯し、かつ
  PPP3/4以上・株価が100日線より上・日経平均がADX20超の上昇トレンド・
  出来高が20日平均の1.5倍以上・日経平均をアウトパフォーム中
- **売り**: 保有60日で手仕舞い、または買値から-10%で損切り（早い方）
- **空売りはやらない**: 逆下半身・戻り売りを実装して検証したが、26年
  4,081トレードで勝率39.1%・平均-1.77%と明確に損失だった（4.4-6参照）

### 自動実行と通知

平日朝8時（JST）にGitHub Actionsで`screen.py`を実行し、上位3銘柄を
ntfy.sh でプッシュ通知する（トピック名はGitHub Secretsの`NTFY_TOPIC`）。

```
本日のおすすめ（すべて現物買い）

[5233]太平洋セメント[押し目]
  買い 4,202円 × 100株 = 420,200円
  利確目安 4,532円(+7.9%) = +33,033円
       到達率67% / 到達なら約10営業日（4〜18日）
  損切り  3,782円(-10%) = -42,020円 ※到達30%
  期限 保有60日で手仕舞い
```

- 利確目安は銘柄ごとのATR（値動きの荒さ）×3から算出。到達率・到達日数は
  過去トレードの実測値であり予測ではない（詳細は4.4-7）
- 銘柄名はEDINET由来の日本語名を使う（`data/japanese_names.json`）
- ⚠️ **売買ルールを変えたら`scripts/notify.py`の統計値も必ず取り直すこと**
  （自動追随しない。取り直し方はREQUIREMENTS.mdの5.1を参照）

ルールの根拠と、採用/不採用にした各案の検証結果は
[REQUIREMENTS.md](REQUIREMENTS.md) の 4.4 節に全て記録してある。

## その他のスクリプト

| スクリプト | 用途 |
|---|---|
| `screen.py` | 本体。今日の推奨銘柄ランキングを出力 |
| `backtest.py` | 売買ルールの検証（トレード単位の勝率・PF） |
| `compare.py` | 複数の売買ルールを1プロセスでまとめて比較し表で出す |
| `price_cache.py` | 株価のローカルキャッシュ（他スクリプトから使う） |
| `portfolio_sim.py` | 予算・コスト・税金を入れた現実的な資産推移の検証 |
| `scripts/build_universe.py` | 全上場銘柄から売買可能な銘柄ユニバースを作る |
| `analyze_sectors.py` | 業種別の偏り・成績・時代による変化の分析 |
| `analyze_targets.py` | 利確目標の方式（ATR・フィボナッチ等）の到達率検証 |
| `scripts/notify.py` | ntfy.sh へのプッシュ通知（GitHub Actionsから呼ばれる） |
| `find_kabu1000_candidates.py` | かぶ1000流の割安株スクリーニング（別系統） |

### ルールを検証するとき

条件を1つずつ `backtest.py` で回すのではなく、`compare.py` にまとめて渡す。
株価を一度だけ用意して全条件を回すので速く、結果も表で並べて比較できる。

```bash
python3 compare.py "timesl trend marketadx volume rs either ; timesl trend marketadx volume rs pullback" --periods 5y,10y,max
```

- 条件の書式は `backtest.py` の引数と同じ。ファイル（1行1条件）でも渡せる
- `--tickers universe.csv` で対象銘柄を差し替えられる
- 採用基準は**5年・10年・26年で一貫して改善すること**（1期間だけの改善は不採用）
- 株価は `data/price_cache/` にキャッシュされる（gitignore済み）。
  おかしくなったら `python3 price_cache.py clear` で消す

## 検証で得られた主な教訓

1. **勝率とPFはトレードオフ**。勝率を上げる手法の多くは、実質的に損切りを
   遅らせる／しないことで買っているだけ（損切りなしタイムストップは勝率
   54.4%と高いが-20%超の大損が2件→50件に激増した）
2. **トレード単位の改善は実運用の優位性に直結しない**。勝率を42.8%→52.0%に
   改善したが、予算制約と税金を入れるとインデックスに負ける
3. **集計で差が見えても、アウトオブサンプルで持続性を確かめること**。
   業種別に明確な成績差（金融58.4% vs テクノロジー46.9%）が出たが、
   年代間の順位相関は-0.30/-0.14と負で、業種フィルターは機能しなかった
4. **既存条件にフィルターを足す方向はほぼ機能しない**。有効だったのは
   同程度の実力を持つ独立したシグナル（押し目買い）を並べることだった
5. **データを疑うこと**。yfinanceの株式分割データ不整合により、5銘柄で
   実際にはあり得ない値動き（日本航空で191,400%等）が記録されていた

## 注意事項

- **自分専用ツールとして作成**。個別銘柄の売買を推奨するものではなく、
  スクリーニング（絞り込み）の参考情報として使うこと。
- 投資判断は自己責任で。他人に見せる/配布する場合は、投資助言業の
  規制（金融商品取引法）に抵触しないよう表示内容に注意すること。
- yfinanceのデータは無保証・遅延あり。重要な判断の前には証券会社の
  公式情報で必ず裏を取ること。
- バックテストの数値は既定で取引コストを含まない。実際の成績はこれより
  低くなる（詳細は [REQUIREMENTS.md](REQUIREMENTS.md) の 7節）。
